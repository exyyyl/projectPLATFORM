# Фактический статус проекта

Актуально на 2026-08-06. Этот файл отличает существующую рабочую реализацию от
моделей Prisma, демонстрационной вёрстки и запланированных возможностей.

## Backend: реализовано

- JWT access/refresh, ротация refresh-токена, logout, guest-only login/register.
- Глобальная защита JWT, `@Public()`, роли и проверка активности пользователя и
  tenant на каждом защищённом запросе.
- Профиль `GET/PUT /api/users/me`.
- Tenant-scoped CRUD пользователей, групп, дисциплин и новостей.
- Назначения студентов в группы, преподавателей и групп в дисциплины, тройная
  связь `преподаватель + дисциплина + группа` (`TeachingAssignment`).
- Role-scoped `/api/academic/overview`.
- Базовый CRUD курса, подключение `TeachingAssignment` к курсу, публикация
  курса, создание/редактирование материала и отдельный график его выпуска для
  каждой группы.
- `CourseTemplate` и независимый запуск на учебный год/семестр; блоки и задания
  копируются снимком, относительный дедлайн считается от `startsAt`.
- CRUD блоков шаблона и запуска курса.
- CRUD заданий запуска и переходы `draft → published → closed`.
- Базовое архивирование запуска с запретом последующих изменений.
- Список уведомлений, отметка прочтения и уведомления при ручной публикации
  материала.
- Markdown-новости на backend: черновик, публикация, аудитория по роли.
- Prisma migrations и повторяемый demo-seed. Суперадминистратор из seed удалён
  и создаётся отдельной CLI-командой.

## Backend: существует только частично

- `Submission` и `SubmissionFile` имеют рабочий multipart API с попытками,
  дедлайнами, файловыми лимитами и уведомлением преподавателя. `Grade` и
  `ChatMessage` пока имеют только Prisma-модели/demo-seed и TODO endpoints.
- Прогресс группы вычисляется по заданиям, сдачам и оценкам; создание заданий и
  сдача файлов уже работают, полноценное выставление оценок через API — TODO.
- Архив запуска уже read-only, но полный исторический сценарий сдач и оценок
  можно завершить только после реализации соответствующих API.
- MinIO поднимается Docker Compose; backend загружает приватные файлы сдач,
  проверяет тип/размер и выдаёт авторизованный presigned URL. Файлы материалов
  шаблона и курса ещё не подключены к этому слою.
- Swagger включён, но не все контракты и варианты ошибок описаны полностью.
- Роль `superadmin` существует, но безопасного выбора активного tenant с аудитом
  ещё нет.

## Backend: отсутствует

- Рабочие API оценок и чата задания; API сдач уже реализован.
- Подключение MinIO-файлов к материалам шаблона и запуска; файловый слой для
  сдач уже реализован.
- Материалы внутри шаблона и их копирование в новый запуск: это следующий этап
  вместе с MinIO. Сейчас клонируются блоки и задания.
- Фоновый worker автоматического выпуска материалов и уведомлений.
- Импорт пользователей CSV и систематический audit log административных
  действий.
- Redis, распределённый rate limit и распределённый кэш.

## Frontend: реализовано

- React/Vite-приложение, общий layout, адаптивные UI-компоненты, тема, роутинг.
- Демонстрационные страницы главной, курсов, материала, новостей, входа и
  профиля.
- Демонстрации TipTap, PDF, формы и таблицы.
- Unit-тесты UI и Playwright-тесты демонстрационной вёрстки и навигации.

## Frontend: отсутствует или является mock

- Вход не обращается к backend и принимает любые поля; авторизация хранится как
  boolean в `localStorage` без access token, refresh и реального logout.
- Профиль, курсы, материалы, прогресс и новости берутся из статических данных.
- Нет role-based интерфейсов студента, преподавателя, администратора и
  суперадминистратора.
- Нет admin dashboard для пользователей, групп, дисциплин, назначений и
  новостей.
- Нет обработки `401` с refresh/retry и очисткой сессии, нет
  `credentials: "include"` для refresh-cookie.
- Единственный фактический API-запрос — health indicator. Сейчас он запрашивает
  `/api/health`, тогда как backend публикует health как `/health`; контракт надо
  выровнять.
- Playwright не запускает backend и не проверяет реальную авторизацию/API.

## Инфраструктура и CI

- Есть Docker Compose для PostgreSQL, MinIO, backend, frontend и Nginx.
- Nginx проксирует `/api/*` в backend, но конфигурация поддоменов platform и
  dashboard ещё не реализована.
- Development Dockerfile backend вызывает отсутствующий script `start:dev`.
- README backend также содержит устаревший `npm run start:dev`; фактическая
  команда — `npm run dev:watch`.
- Dockerfile использует Node 20, а README/CI — Node 22; версию нужно унифицировать.
- CI запускает build/lint/unit для backend и frontend и Playwright для frontend,
  но не запускает backend E2E с PostgreSQL.
- Redis-сервиса в Compose и Redis-клиента в backend нет.

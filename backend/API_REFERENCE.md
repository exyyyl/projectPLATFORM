# API Reference

Документ описывает только реализованные маршруты. Заглушки перечислены отдельно
и не считаются готовым API-контрактом.

Интерактивная документация после запуска backend:

- Swagger UI: `http://localhost:3000/docs`
- OpenAPI JSON: `http://localhost:3000/docs-json`

Быстрый полный список всех controller routes и их готовность:
`API_ROUTE_MATRIX.md`.

Для каждого готового контракта фиксируются: HTTP method и URL, авторизация и
роли, tenant/ownership-ограничение, path/query/body, успешный HTTP status и
тело, ошибки, побочные эффекты, правила дат и идемпотентность. Заглушки имеют
только пометку TODO и не являются контрактом для frontend.

## Общие правила

| Параметр           | Значение                              |
| ------------------ | ------------------------------------- |
| Локальный base URL | `http://localhost:3000`               |
| API prefix         | `/api`                                 |
| Формат тела        | `application/json`                    |
| Access token       | `Authorization: Bearer <accessToken>` |
| Refresh token      | HttpOnly cookie `refreshToken`        |
| Время              | ISO 8601, UTC                         |

Глобальный `ValidationPipe` удалять неизвестные поля не будет: запрос с лишним
полем получит `400 Bad Request`.

Стандартная ошибка NestJS:

```json
{
  "statusCode": 400,
  "message": ["property role should not exist"],
  "error": "Bad Request"
}
```

`message` может быть строкой или массивом сообщений валидации.

## Auth

### POST `/api/auth/register`

Создаёт студента и сразу выдаёт пару токенов. Маршрут доступен только гостю:
активный access token или действующая refresh-сессия дают `403`.

Тело:

```json
{
  "email": "new-student@example.com",
  "password": "password123",
  "name": "Новый студент"
}
```

| Поле       | Тип    | Обязательно | Ограничения        |
| ---------- | ------ | ----------: | ------------------ |
| `email`    | string |          да | корректный email   |
| `password` | string |          да | минимум 8 символов |
| `name`     | string |         нет | имя пользователя   |

Успех — `201 Created`:

```json
{
  "accessToken": "<jwt>"
}
```

Дополнительно сервер устанавливает cookie:

```http
Set-Cookie: refreshToken=<jwt>; HttpOnly; SameSite=Strict; Path=/
```

| Статус | Когда                                            |
| -----: | ------------------------------------------------ |
|  `201` | пользователь создан                              |
|  `400` | DTO не прошёл валидацию или переданы лишние поля |
|  `401` | передан некорректный access token/header         |
|  `403` | пользователь уже авторизован                     |
|  `409` | email уже существует или tenant ещё не настроен  |
|  `429` | превышен глобальный rate limit                   |

Текущее dev-поведение: регистрация добавляет пользователя в первый настроенный
tenant. До production необходимо добавить явное определение tenant по домену или
приглашению.

### POST `/api/auth/login`

Авторизует активного пользователя по email и паролю. Доступен только гостю.

Тело:

```json
{
  "email": "student@demo.local",
  "password": "demo123"
}
```

Успех — `201 Created`:

```json
{
  "accessToken": "<jwt>"
}
```

Refresh token возвращается только в HttpOnly cookie.

| Статус | Когда                                                      |
| -----: | ---------------------------------------------------------- |
|  `201` | email и пароль корректны                                   |
|  `400` | некорректный email, тип поля или лишнее поле               |
|  `401` | неверные credentials либо некорректный access token/header |
|  `403` | уже существует активная access/refresh-сессия              |
|  `429` | превышен rate limit                                        |

### POST `/api/auth/admin/login`

Отдельная точка входа для dashboard. Тело и успешный ответ совпадают с обычным
login, но токены выдаются только активному `admin` или `superadmin`:

```json
{
  "email": "admin@demo.local",
  "password": "demo123"
}
```

Успех — `201 Created`, в JSON возвращается `accessToken`, refresh token
устанавливается в HttpOnly cookie. Студент или преподаватель получает `401`,
даже если пароль указан верно. Проверка не дублирует систему авторизации:
обычный и admin login используют один `AuthService`.

| Статус | Когда                                                    |
| -----: | -------------------------------------------------------- |
|  `201` | credentials верны и роль — `admin` или `superadmin`      |
|  `400` | тело не прошло DTO-валидацию                              |
|  `401` | неверные credentials, неактивный аккаунт или роль не admin |
|  `403` | в cookie/header уже существует активная сессия            |
|  `429` | превышен rate limit                                      |

### POST `/api/auth/refresh`

Тело не требуется. Читает cookie `refreshToken`, отзывает использованный refresh
token и возвращает новую пару. Повторное использование старой cookie невозможно.

Успех — `201 Created`:

```json
{
  "accessToken": "<new-jwt>"
}
```

Также устанавливается новая cookie `refreshToken`.

| Статус | Когда                                                            |
| -----: | ---------------------------------------------------------------- |
|  `201` | refresh token действителен и успешно ротирован                   |
|  `401` | cookie отсутствует, истекла, отозвана или имеет неверную подпись |
|  `429` | превышен rate limit                                              |

### POST `/api/auth/logout`

Тело не требуется. Если refresh cookie существует, её запись удаляется из БД.
Cookie очищается в любом случае, поэтому повторный logout безопасен.

Успех — `201 Created`:

```json
{
  "message": "Logged out"
}
```

## Профиль пользователя

Все маршруты раздела требуют access token.

### GET `/api/users/me`

Возвращает активного пользователя только внутри `tenantId` из access token.

Успех — `200 OK`:

```json
{
  "id": 4,
  "tenantId": 1,
  "email": "student@demo.local",
  "fullName": "Иван Студентов",
  "role": "student",
  "isActive": true,
  "createdAt": "2026-05-24T06:35:18.320Z",
  "updatedAt": "2026-05-24T06:35:18.320Z"
}
```

`passwordHash` не возвращается.

| Статус | Когда                                                        |
| -----: | ------------------------------------------------------------ |
|  `200` | профиль найден                                               |
|  `401` | access token отсутствует/некорректен либо аккаунт недоступен |
|  `429` | превышен rate limit                                          |

### PUT `/api/users/me`

Изменяет имя, пароль или оба поля. Изменять `email`, `role`, `tenantId` и
`isActive` через этот маршрут нельзя.

Только имя:

```json
{
  "fullName": "Новое имя"
}
```

Имя и пароль:

```json
{
  "fullName": "Новое имя",
  "currentPassword": "старый-пароль",
  "newPassword": "новый-пароль"
}
```

| Поле              | Тип    |      Обязательно | Ограничения                       |
| ----------------- | ------ | ---------------: | --------------------------------- |
| `fullName`        | string |              нет | после trim от 2 до 200 символов   |
| `currentPassword` | string | при смене пароля | передаётся вместе с `newPassword` |
| `newPassword`     | string | при смене пароля | от 8 до 72 символов               |

Успех — `200 OK`: публичный объект пользователя в том же формате, что у
`GET /api/users/me`.

После смены пароля все refresh-сессии пользователя отзываются. Текущий access
token продолжает работать до своего истечения.

| Статус | Когда                                                                               |
| -----: | ----------------------------------------------------------------------------------- |
|  `200` | профиль обновлён                                                                    |
|  `400` | пустое тело, лишние поля, неверные ограничения или передано только одно поле пароля |
|  `401` | access token/аккаунт недоступен либо текущий пароль неверен                         |
|  `429` | превышен rate limit                                                                 |

## Администрирование

### GET `/api/admin/users`

Требует access token с ролью `admin`. Возвращает страницу пользователей только
из tenant текущего администратора.

Query-параметры:

| Параметр  | Тип     | По умолчанию | Ограничения                                      |
| --------- | ------- | ------------ | ------------------------------------------------ |
| `page`    | integer | `1`          | минимум `1`                                      |
| `limit`   | integer | `20`         | от `1` до `100`                                  |
| `search`  | string  | —            | поиск без учёта регистра по email и полному имени |
| `role`    | enum    | —            | `student`, `teacher` или `admin`                  |
| `isActive`| string  | —            | `true` или `false`                                |

Пример:

```http
GET /api/admin/users?page=1&limit=20&search=иван&role=student&isActive=true
```

Успех — `200 OK`:

```json
{
  "items": [
    {
      "id": 4,
      "tenantId": 1,
      "email": "student@demo.local",
      "fullName": "Иван Студентов",
      "role": "student",
      "isActive": true,
      "createdAt": "2026-05-24T06:35:18.320Z",
      "updatedAt": "2026-05-24T06:35:18.320Z"
    }
  ],
  "pagination": {
    "page": 1,
    "limit": 20,
    "total": 1,
    "totalPages": 1
  }
}
```

| Статус | Когда                                    |
| -----: | ---------------------------------------- |
|  `200` | список получен                           |
|  `400` | query-параметры не прошли валидацию      |
|  `401` | access token отсутствует или некорректен |
|  `403` | роль пользователя не `admin`             |
|  `429` | превышен rate limit                      |

### POST `/api/admin/users`

Создаёт пользователя в tenant текущего администратора. `tenantId` нельзя
передать в теле запроса.

```json
{
  "email": "new-user@demo.local",
  "fullName": "Новый пользователь",
  "role": "student",
  "password": "password123",
  "isActive": true
}
```

| Поле       | Тип     | Обязательно | Ограничения                         |
| ---------- | ------- | ----------: | ----------------------------------- |
| `email`    | string  |          да | корректный email                    |
| `fullName` | string  |          да | после trim от 2 до 200 символов     |
| `role`     | enum    |          да | `student`, `teacher` или `admin`     |
| `password` | string  |          да | от 8 до 72 символов                 |
| `isActive` | boolean |         нет | по умолчанию `true`                 |

Успех — `201 Created`: публичный объект созданного пользователя без
`passwordHash`.

| Статус | Когда                                            |
| -----: | ------------------------------------------------ |
|  `201` | пользователь создан                              |
|  `400` | DTO не прошёл валидацию или есть неизвестное поле |
|  `401` | access token отсутствует или некорректен         |
|  `403` | роль пользователя не `admin`                     |
|  `409` | email уже занят внутри tenant                    |
|  `429` | превышен rate limit                              |

### GET `/api/admin/users/:id`

Возвращает публичный объект пользователя, только если он принадлежит tenant
текущего администратора. Чужой tenant и несуществующий ID одинаково дают `404`.

| Статус | Когда                                    |
| -----: | ---------------------------------------- |
|  `200` | пользователь найден                     |
|  `400` | `id` не является целым числом           |
|  `401` | access token отсутствует или некорректен |
|  `403` | роль пользователя не `admin`             |
|  `404` | пользователь в текущем tenant не найден  |

### PUT `/api/admin/users/:id`

Изменяет одно или несколько разрешённых полей пользователя:

```json
{
  "fullName": "Новое имя",
  "role": "teacher",
  "password": "new-password",
  "isActive": true
}
```

Разрешены `email`, `fullName`, `role`, `password`, `isActive`. Пустое тело
получит `400`. Нельзя изменить `tenantId`. Администратор также не может снять
с себя роль `admin` или деактивировать собственный аккаунт.

При изменении email, пароля, роли или деактивации все refresh-сессии изменяемого
пользователя отзываются. Уже выданный access token действует до истечения TTL.

Успех — `200 OK`: обновлённый публичный объект пользователя.

| Статус | Когда                                                  |
| -----: | ------------------------------------------------------ |
|  `200` | пользователь обновлён                                  |
|  `400` | некорректное/пустое тело или запрещённое изменение себя |
|  `401` | access token отсутствует или некорректен               |
|  `403` | роль пользователя не `admin`                           |
|  `404` | пользователь в текущем tenant не найден                |
|  `409` | новый email уже занят внутри tenant                    |

### DELETE `/api/admin/users/:id`

Выполняет безопасное удаление: строка пользователя и связанные учебные данные
не удаляются, вместо этого устанавливается `isActive=false` и отзываются все
refresh-сессии. Текущий администратор не может деактивировать сам себя.

Успех — `200 OK`: публичный объект пользователя с `isActive: false`.

| Статус | Когда                                                 |
| -----: | ----------------------------------------------------- |
|  `200` | пользователь деактивирован                            |
|  `400` | некорректный ID или попытка деактивировать самого себя |
|  `401` | access token отсутствует или некорректен              |
|  `403` | роль пользователя не `admin`                          |
|  `404` | пользователь в текущем tenant не найден               |

`POST /api/admin/users/import` пока остаётся отдельной TODO-заглушкой: импорт CSV
будет реализован после CRUD групп, поскольку для импорта нужно валидировать и
назначать учебные группы.

## Администрирование групп

Все маршруты требуют access token с ролью `admin` и работают только внутри
`tenantId` текущего администратора.

### GET `/api/admin/groups`

Возвращает группы с количеством назначенных студентов.

| Query-параметр | Тип     | По умолчанию | Ограничения                    |
| -------------- | ------- | ------------ | ------------------------------ |
| `page`         | integer | `1`          | минимум `1`                    |
| `limit`        | integer | `20`         | от `1` до `100`                |
| `search`       | string  | —            | поиск по названию и направлению |
| `courseYear`   | integer | —            | от `1` до `6`                  |

Успех — `200 OK`:

```json
{
  "items": [
    {
      "id": 1,
      "tenantId": 1,
      "name": "ИВТ-21",
      "courseYear": 2,
      "direction": "Программная инженерия",
      "studentCount": 2
    }
  ],
  "pagination": {
    "page": 1,
    "limit": 20,
    "total": 1,
    "totalPages": 1
  }
}
```

### POST `/api/admin/groups`

```json
{
  "name": "ИВТ-24",
  "courseYear": 2,
  "direction": "Программная инженерия"
}
```

`name` обязателен, после trim содержит от 2 до 100 символов. `courseYear` и
`direction` необязательны. Название уникально внутри tenant.

Успех — `201 Created`: объект группы с `studentCount: 0` и `students: []`.

### GET `/api/admin/groups/:id`

Возвращает группу и назначенных студентов:

```json
{
  "id": 1,
  "tenantId": 1,
  "name": "ИВТ-21",
  "courseYear": 2,
  "direction": "Программная инженерия",
  "studentCount": 1,
  "students": [
    {
      "id": 4,
      "email": "student@demo.local",
      "fullName": "Иван Студентов",
      "isActive": true
    }
  ]
}
```

### PUT `/api/admin/groups/:id`

Изменяет `name`, `courseYear` и/или `direction`. Пустое тело получает `400`.
Успех — `200 OK` с полной группой и студентами.

### DELETE `/api/admin/groups/:id`

Физически удаляет группу. Связи со студентами, дисциплинами и тройные назначения
удаляются каскадно. Пользователи не удаляются. Успех — `200 OK` с удалённой
группой.

### POST `/api/admin/groups/:id/students`

Добавляет одного или несколько активных студентов:

```json
{
  "studentIds": [4, 5]
}
```

Все ID должны принадлежать текущему tenant, иметь роль `student` и
`isActive=true`. Повторное назначение безопасно и не создаёт дубликат. Успех —
`200 OK` с обновлённой группой.

### DELETE `/api/admin/groups/:id/students/:studentId`

Удаляет назначение студента на группу, но не самого пользователя. Успех —
`200 OK`; отсутствующая связь получает `404`.

Общие исходы группы:

| Статус | Когда                                                       |
| -----: | ----------------------------------------------------------- |
|  `400` | DTO/ID некорректны, тело пустое или пользователь не студент |
|  `401` | access token отсутствует или некорректен                    |
|  `403` | роль пользователя не `admin`                                |
|  `404` | группа или назначение не найдено внутри tenant               |
|  `409` | название группы уже существует внутри tenant                 |
|  `429` | превышен rate limit                                         |

## Администрирование дисциплин

### GET `/api/admin/disciplines`

Параметры `page`, `limit` и `search` работают аналогично списку групп. Элемент
списка содержит `teacherCount`, `groupCount` и `teachingAssignmentCount`.

### POST `/api/admin/disciplines`

```json
{
  "name": "Проектирование ПО",
  "description": "Архитектура и жизненный цикл программных систем"
}
```

Название обязательно, уникально внутри tenant и содержит от 2 до 200 символов.
Описание необязательно, максимум 5000 символов. Успех — `201 Created`.

### GET `/api/admin/disciplines/:id`

Возвращает дисциплину, парные связи и конкретные тройные назначения:

```json
{
  "id": 1,
  "tenantId": 1,
  "name": "Алгоритмы и структуры данных",
  "description": "Базовые алгоритмы",
  "teacherCount": 1,
  "groupCount": 1,
  "teachingAssignmentCount": 1,
  "teachers": [
    {
      "id": 2,
      "email": "teacher@demo.local",
      "fullName": "Павел Преподаватель",
      "isActive": true
    }
  ],
  "groups": [
    {
      "id": 1,
      "name": "ИВТ-21",
      "courseYear": 2,
      "direction": "Программная инженерия"
    }
  ],
  "teachingAssignments": [
    {
      "id": 1,
      "createdAt": "2026-08-01T10:00:00.000Z",
      "teacher": { "id": 2, "email": "teacher@demo.local" },
      "group": { "id": 1, "name": "ИВТ-21" }
    }
  ]
}
```

### PUT `/api/admin/disciplines/:id`

Изменяет `name` и/или `description`. Пустое тело получает `400`. Успех —
`200 OK` с полной дисциплиной и назначениями.

### DELETE `/api/admin/disciplines/:id`

Удаляет дисциплину и её назначения только когда у дисциплины нет курсов. Если
курсы существуют, возвращается `409 Conflict`, чтобы случайно не удалить блоки,
задания и работы студентов.

### POST `/api/admin/disciplines/:id/teachers`

```json
{ "teacherIds": [2, 3] }
```

Добавляет активных пользователей с ролью `teacher` из текущего tenant. Успех —
`200 OK` с обновлённой дисциплиной.

### DELETE `/api/admin/disciplines/:id/teachers/:teacherId`

Удаляет парное назначение преподавателя и все тройные назначения этого
преподавателя по данной дисциплине.

### POST `/api/admin/disciplines/:id/groups`

```json
{ "groupIds": [1, 2] }
```

Добавляет группы текущего tenant. Успех — `200 OK`.

### DELETE `/api/admin/disciplines/:id/groups/:groupId`

Удаляет парное назначение группы и все тройные назначения этой группы по данной
дисциплине.

### POST `/api/admin/disciplines/:id/teaching-assignments`

Создаёт конкретную тройку «преподаватель ведёт дисциплину у группы»:

```json
{
  "teacherId": 2,
  "groupId": 1
}
```

Преподаватель должен быть активным `teacher`, а группа и преподаватель должны
принадлежать tenant администратора. До создания тройки преподаватель должен
быть назначен дисциплине через `/teachers`, а группа — через `/groups`. Если
одной из предварительных связей нет, backend возвращает `409 Conflict`.
Одинаковую тройку нельзя создать дважды.

Успех — `201 Created`:

```json
{
  "id": 1,
  "createdAt": "2026-08-01T10:00:00.000Z",
  "teacher": {
    "id": 2,
    "email": "teacher@demo.local",
    "fullName": "Павел Преподаватель",
    "isActive": true
  },

    "id": 1,
    "name": "ИВТ-21",

    "direction": "Программная инженерия"
  }
```

### DELETE `/api/admin/disciplines/:id/teaching-assignments/:assignmentId`

Удаляет только конкретную тройку. Общие парные назначения преподавателя и
группы к дисциплине сохраняются.

Общие исходы дисциплин и назначений:

| Статус | Когда                                                        |
| -----: | ------------------------------------------------------------ |
|  `400` | DTO/ID некорректны, teacher/group не подходят по tenant/роли |
|  `401` | access token отсутствует или некорректен                     |
|  `403` | роль пользователя не `admin`                                 |
|  `404` | дисциплина, связь или назначение не найдены                   |
|  `409` | дубликат имени/тройки либо удаляемая дисциплина имеет курсы   |
|  `429` | превышен rate limit                                          |

## Шаблоны и запуски курса

Шаблон — редактируемая заготовка преподавателя. Запуск (`Course`) — независимый
снимок на учебный год. Изменение шаблона не меняет уже созданный запуск.

Все routes шаблонов требуют access JWT. Допуск: владелец с ролью `teacher`,
`admin` того же tenant и `superadmin`. Студент получает `403` на весь раздел.

### GET `/api/course-templates`

Тело отсутствует. Возвращает `200 OK` со списком доступных шаблонов,
дисциплиной, владельцем и `_count.blocks`, `_count.assignments`, `_count.runs`.

### POST `/api/course-templates`

Создаёт активный шаблон версии `1`. Преподаватель не передаёт `ownerId`;
admin/superadmin указывает преподавателя, предварительно назначенного дисциплине.

```json
{
  "disciplineId": 1,
  "ownerId": 2,
  "title": "Основы алгоритмизации",
  "description": "Шаблон для ежегодного запуска"
}
```

Успех — `201 Created`: шаблон с `blocks`, `assignments` и `runs`.

### GET `/api/course-templates/:id`

Возвращает `200 OK`: метаданные, текущую `version`, `isActive`, отсортированные
блоки, задания шаблона и краткий список созданных запусков.

### PUT `/api/course-templates/:id`

Принимает хотя бы одно поле `title` или `description`. Успех — `200 OK`.
Каждое изменение увеличивает `version`; старые запуски сохраняют записанный
`templateVersion`.

### DELETE `/api/course-templates/:id`

Не удаляет историю физически. Выставляет `isActive=false`, увеличивает version и
возвращает `200 OK`. Существующие запуски продолжают читаться, но создавать из
неактивного шаблона новые нельзя (`409`).

### Блоки шаблона

Routes:

- `GET /api/course-templates/:id/blocks` → `200`, отсортированный массив;
- `POST /api/course-templates/:id/blocks` → `201`, созданный блок;
- `PUT /api/course-templates/:id/blocks/:blockId` → `200`, обновлённый блок;
- `DELETE /api/course-templates/:id/blocks/:blockId` → `200`, удалённый блок.

Создание:

```json
{
  "title": "Модуль 1. Основы",
  "orderIndex": 1,
  "content": { "kind": "rich-text", "text": "Введение" }
}
```

`title` — 2–200 символов, `orderIndex` — целое от `0`, `content` — JSON object.
PUT принимает любое непустое подмножество этих полей. Удаление блока оставляет
задания шаблона, но сбрасывает у них `blockId` в `null`.

### Задания шаблона

Routes:

- `GET /api/course-templates/:id/assignments` → `200`, массив;
- `POST /api/course-templates/:id/assignments` → `201`, созданное задание;
- `PUT /api/course-templates/:id/assignments/:assignmentId` → `200`;
- `DELETE /api/course-templates/:id/assignments/:assignmentId` → `200`.

```json
{
  "blockId": 10,
  "title": "Практика по алгоритмам",
  "description": "Решите задачи и приложите архив",
  "gradingType": "scored",
  "maxScore": 100,
  "deadlineOffsetDays": 14,
  "allowedExtensions": ["pdf"],
  "maxAttempts": 5,
  "maxFiles": 1,
  "maxFileSizeBytes": 5242880,
  "maxTotalSizeBytes": 5242880,
  "allowLateSubmissions": false
}
```

- `gradingType`: `scored` требует `maxScore`; `pass_fail` запрещает его;
- `deadlineOffsetDays`: `0..3660`, считается от `startsAt` будущего запуска;
- расширения: максимум 20, без точки, `a-z`, цифры, длина до 10; backend
  приводит их к lower-case, удаляет ведущую точку и дубликаты;
- лимиты и разрешение поздней сдачи копируются в каждый новый запуск курса;
- MinIO upload проверяет размер, MIME и magic bytes; исполняемые расширения
  запрещены глобально.

### POST `/api/course-templates/:id/runs`

Создаёт новый `Course` в `draft` и копирует блоки и задания отдельными строками.

```json
{
  "academicYear": "2026/2027",
  "semester": 1,
  "startsAt": "2026-09-01T09:00:00.000Z",
  "endsAt": "2027-01-20T09:00:00.000Z",
  "teachingAssignmentIds": [7, 8]
}
```

Необязательные поля: `teacherId` для admin/superadmin и собственный `title`.
Год обязан содержать последовательные годы; semester `1..3`; `endsAt` позже
`startsAt`. Если есть относительный дедлайн, `startsAt` обязателен.

Каждый `teachingAssignmentId` должен иметь ту же дисциплину и преподавателя.
Успех — `201 Created`: запуск с template, teacher, discipline, blocks,
assignments и courseGroups. Повтор той же комбинации
template/teacher/year/semester даёт `409`.

Материалы шаблона пока не копируются: их metadata и MinIO-файлы будут добавлены
следующим этапом. Материалы существующего запуска продолжают работать через
routes курса ниже.

Общие исходы шаблонов:

| Статус | Когда |
| -----: | --- |
| `400` | DTO, год, диапазон дат, JSON блока или grading-настройки некорректны |
| `401` | access JWT отсутствует/некорректен или аккаунт неактивен |
| `403` | роль, tenant или ownership не разрешают действие |
| `404` | шаблон, блок, задание, дисциплина не найдены |
| `409` | шаблон неактивен, teacher не назначен, группы не совпадают или run уже есть |
| `429` | превышен глобальный rate limit |

## Курсы и выпуск материалов

### GET `/api/courses`

Возвращает студенту только опубликованные курсы его групп, преподавателю — его
курсы, администратору — курсы tenant, суперадмину — все курсы. Элемент содержит
`academicYear`, `semester`, `startsAt`, `endsAt`, `archivedAt`, `templateVersion`
и краткий `template`, если запуск создан из шаблона.

### POST `/api/courses`

Роли: `teacher`, `admin`, `superadmin`. Создаёт legacy/manual `draft` без
шаблона и учебного года:

```json
{
  "disciplineId": 1,
  "teacherId": 2,
  "title": "Математика, осенний семестр",
  "description": "Подготовленный заранее курс"
}
```

Преподаватель не передаёт `teacherId`: backend использует ID из токена.
Администратор обязан передать активного преподавателя, уже назначенного этой
дисциплине.

Для ежегодного рабочего процесса frontend должен предпочитать
`POST /api/course-templates/:id/runs`.

### GET `/api/courses/:id`

Преподаватель и администратор получают все группы, задания, блоки, материалы и
настройки выпусков. Студент получает только свои группы и материалы, которые
уже опубликованы либо достигли своей даты выпуска.

### PUT `/api/courses/:id`

Изменяет `title` и/или `description`. Только владелец-преподаватель,
администратор tenant или суперадмин.

### POST `/api/courses/:id/publish`

Публикует курс — `200 OK`. После этого курс появляется у студентов подключённых
групп, но каждый материал всё равно проверяет собственную дату выпуска.

### POST `/api/courses/:id/unpublish`

Возвращает курс в черновики — `200 OK`.

### POST `/api/courses/:id/archive`

Переводит запуск в `archived`, устанавливает `archivedAt` и возвращает
`200 OK`. Архив остаётся доступен владельцу, admin и superadmin для истории, но
его metadata, группы, блоки, материалы и задания больше нельзя изменять. Для
студента архивный запуск не входит в список активных курсов.

### Блоки запуска

- `GET /api/courses/:id/blocks` — роли с доступом к запуску, `200`, массив;
- `POST /api/courses/:id/blocks` — owner-teacher/admin/superadmin, `201`;
- `PUT /api/courses/:id/blocks/:blockId` — owner-teacher/admin/superadmin,
  `200`;
- `DELETE /api/courses/:id/blocks/:blockId` — owner-teacher/admin/superadmin,
  `200`.

DTO создания и обновления совпадает с блоками шаблона. Удаление блока не удаляет
материалы и задания: их `blockId` становится `null`. Любое изменение архива
возвращает `409`.

### POST `/api/courses/:id/groups`

Подключает группы через существующие тройные назначения:

```json
{
  "teachingAssignmentIds": [7, 8]
}
```

Каждое назначение обязано совпадать с преподавателем и дисциплиной курса.
Для уже созданных материалов автоматически формируются групповые выпуски.

### DELETE `/api/courses/:id/groups/:courseGroupId`

Отключает группу от курса вместе с её настройками выпусков материалов.

### GET `/api/courses/:id/groups/:courseGroupId/progress`

Роли: владелец-преподаватель, admin, superadmin. Для каждого активного студента
возвращает `submittedAssignments`, `gradedAssignments`, `passedAssignments`,
`pendingReview` и `progressPercent`.

### POST `/api/courses/:id/materials`

Создаёт материал и сохраняет `createdAt`, `updatedAt` и общую дату:

```json
{
  "title": "Лекция 1",
  "type": "link",
  "url": "https://example.com/lecture-1",
  "defaultAvailableAt": "2026-10-07T09:00:00.000Z"
}
```

Для `type=link` обязателен `url`; для `type=file` обязателен внутренний
`filePath`, который в будущем будет возвращать модуль загрузки MinIO.

### PUT `/api/courses/:id/materials/:materialId`

Изменяет данные материала. Новая общая дата применяется только к выпускам без
индивидуального переопределения и не переносит уже опубликованные материалы.

### PUT `/api/courses/:id/materials/:materialId/groups/:courseGroupId/release`

Управляет одной группой независимо от остальных:

```json
{ "action": "publish_now" }
```

или:

```json
{
  "action": "schedule",
  "scheduledAt": "2026-10-10T09:00:00.000Z"
}
```

Действия: `inherit`, `schedule`, `publish_now`, `withhold`. `publish_now`
немедленно создаёт уведомления студентам выбранной группы.

Общие исходы курсов:

| Статус | Когда                                                        |
| -----: | ------------------------------------------------------------ |
|  `400` | DTO некорректен, отсутствует дата или источник материала    |
|  `401` | access token отсутствует или некорректен                     |
|  `403` | роль или принадлежность курса не разрешает действие          |
|  `404` | курс, группа, материал или блок не найдены                    |
|  `409` | архив read-only либо teacher/group не соответствуют назначению |

## Задания запуска курса

Student читает только задания `published` и `closed` опубликованного курса своей
группы. Teacher управляет только своими запусками, admin — своим tenant,
superadmin — любым доступным запуском.

### GET `/api/courses/:courseId/assignments`

Тело отсутствует. Успех — `200 OK`, массив заданий. Teacher/admin получает также
draft; student — только published/closed.

### POST `/api/courses/:courseId/assignments`

Создаёт `draft`; роли owner-teacher/admin/superadmin.

```json
{
  "blockId": 15,
  "title": "Лабораторная работа №1",
  "description": "Приложите исходный код и отчёт",
  "gradingType": "scored",
  "maxScore": 100,
  "deadline": "2026-10-10T20:59:59.000Z",
  "allowedExtensions": ["pdf"],
  "maxAttempts": 5,
  "maxFiles": 1,
  "maxFileSizeBytes": 5242880,
  "maxTotalSizeBytes": 5242880,
  "allowLateSubmissions": false
}
```

`blockId`, `description`, `deadline`, `allowedExtensions` необязательны. Правила
grading и расширений совпадают с шаблоном. Успех — `201 Created`:

```json
{
  "id": 31,
  "courseId": 12,
  "blockId": 15,
  "title": "Лабораторная работа №1",
  "gradingType": "scored",
  "maxScore": 100,
  "deadline": "2026-10-10T20:59:59.000Z",
  "status": "draft",
  "allowedExtensions": ["zip", "pdf"],
  "createdAt": "2026-08-10T10:00:00.000Z",
  "updatedAt": "2026-08-10T10:00:00.000Z",
  "block": { "id": 15, "title": "Практика", "orderIndex": 2 },
  "course": { "id": 12, "title": "Основы алгоритмизации" },
  "_count": { "submissions": 0 }
}
```

### GET `/api/assignments/:id`

Возвращает `200 OK` в том же формате. Недоступный курс и draft для студента
маскируются как `404`.

### PUT `/api/assignments/:id`

Принимает непустое подмножество полей POST; `blockId`, `maxScore` и `deadline`
могут быть `null`. После первой сдачи нельзя менять `gradingType` и `maxScore`.
`maxAttempts` нельзя уменьшить ниже уже существующего номера попытки.
Закрытое задание и архивный курс read-only. Успех — `200 OK`.

### POST `/api/assignments/:id/publish`

Тело отсутствует. Переводит `draft → published`, повторный вызов для published
идемпотентен. Closed повторно открыть нельзя. Успех — `200 OK`.

### POST `/api/assignments/:id/close`

Тело отсутствует. Переводит `published → closed`; повтор для closed безопасен.
Draft сначала нужно опубликовать. Успех — `200 OK`.

### DELETE `/api/assignments/:id`

Физически удаляет только draft без сдач и возвращает удалённую запись —
`200 OK`. Published, closed или задание со сдачами возвращает `409`.

Общие исходы заданий:

| Статус | Когда |
| -----: | --- |
| `400` | DTO/ID, дата, расширения или grading-настройки некорректны |
| `401` | access JWT отсутствует/некорректен или аккаунт неактивен |
| `403` | роль или ownership не разрешает запись |
| `404` | задание, блок, курс не найдены/не видны пользователю |
| `409` | неверный переход статуса, есть сдачи или course archived |
| `429` | превышен rate limit |

Ограничения сдачи сохраняются вместе с заданием и копируются из шаблона в запуск:

- `maxAttempts`: `1..20`, по умолчанию `3`;
- `maxFiles`: `1..10`, по умолчанию `5`;
- `maxFileSizeBytes`: `1024..104857600`, по умолчанию `26214400`;
- `maxTotalSizeBytes`: не меньше лимита одного файла и не больше `262144000`;
- `allowLateSubmissions`: по умолчанию `false`;
- `allowedExtensions`: пустой массив разрешает все поддерживаемые безопасные
  форматы; непустой массив дополнительно сужает список.

Кроме лимита задания действует более строгий из server ceilings:
`UPLOAD_HARD_MAX_FILES` (по умолчанию 5),
`UPLOAD_HARD_MAX_FILE_SIZE_BYTES` (25 МБ) и
`UPLOAD_HARD_MAX_TOTAL_SIZE_BYTES` (100 МБ). Задание с настройками выше server
ceiling не создаётся. Это не позволяет преподавателю или подменённому запросу
ослабить инфраструктурную защиту.

Исполняемые и неподдерживаемые расширения нельзя сохранить в настройках.
Backend проверяет расширение, заявленный MIME и сигнатуру/содержимое файла.

## Сдачи и приватные файлы MinIO

### POST `/api/assignments/:assignmentId/submissions`

Только `student`. Запрос `multipart/form-data`; `studentId` не принимается и
всегда берётся из JWT.

| Поле | Обязательно | Описание |
| --- | --- | --- |
| `files` | да | один или несколько бинарных файлов под одинаковым именем поля |
| `studentComment` | нет | строка до 2000 символов |

Пример с настройками `5 попыток / 1 PDF / 5 МБ`: backend разрешит студенту
создать попытки с номерами `1..5`; шестая получит `409`. Каждый запрос должен
содержать ровно один файл из-за `maxFiles: 1`, а PDF проверяется не только по
имени и MIME, но и по сигнатуре `%PDF-`.

Успех — `201 Created`:

```json
{
  "id": 41,
  "assignmentId": 31,
  "studentId": 12,
  "attemptNumber": 1,
  "studentComment": "Первая версия",
  "submittedAt": "2026-10-01T12:00:00.000Z",
  "student": {
    "id": 12,
    "fullName": "Иванов Иван Иванович",
    "email": "student@demo.local"
  },
  "files": [
    {
      "id": 55,
      "originalName": "report.pdf",
      "mimeType": "application/pdf",
      "sizeBytes": 245760
    }
  ],
  "grade": null
}
```

Перед загрузкой проверяются: опубликованные assignment/course, членство студента
в группе курса, дедлайн, лимит попыток, число файлов, размер файла и всей
попытки, разрешённое расширение, MIME и magic bytes. Объект получает случайный
внутренний key; исходное имя не используется как путь. После успешной транзакции
преподаватель получает `submission_received` notification.

| Статус | Когда |
| ---: | --- |
| `400` | нет файлов, превышен файловый лимит, формат/MIME/содержимое не совпадают |
| `401` | JWT отсутствует или недействителен |
| `403` | роль не student |
| `404` | задание не опубликовано или студент не состоит в группе курса |
| `409` | истёк дедлайн без late-разрешения либо исчерпаны попытки |
| `413` | multipart отклонён абсолютным лимитом Nest/Multer |
| `503` | MinIO недоступен |

### GET `/api/assignments/:assignmentId/submissions`

Teacher-владелец курса, admin своего tenant и superadmin получают `200 OK` с
массивом попыток, студентами, метаданными файлов и оценками. Чужой курс даёт
`403`, отсутствующее задание — `404`.

### GET `/api/files/:id/download`

`id` — идентификатор `SubmissionFile`, а не путь MinIO. Получить ссылку может
сам студент-владелец, преподаватель курса, admin tenant или superadmin. Ответ:

```json
{
  "id": 55,
  "originalName": "report.pdf",
  "mimeType": "application/pdf",
  "sizeBytes": 245760,
  "url": "http://localhost:9000/uploads/...signature...",
  "expiresInSeconds": 300
}
```

Bucket не публикуется. URL подписан MinIO и по умолчанию живёт 5 минут.
В Docker `MINIO_ENDPOINT=minio` используется только backend-клиентом, а URL для
браузера подписывается через `MINIO_PUBLIC_ENDPOINT`. Локально это `localhost`;
в production должен быть HTTPS-host файлового хранилища/reverse proxy.

### PATCH `/api/notifications/:id/read`

## Новости пользователя

Все маршруты требуют access token. Пользователь видит только опубликованные
новости своего tenant с аудиторией `all` или своей ролью. Скрытая из-за статуса
или роли новость возвращает `404`, чтобы не раскрывать её существование.

### GET `/api/news`

Query-параметры: `page` (по умолчанию `1`), `limit` (`20`, максимум `100`) и
необязательный `search` по заголовку/аннотации.

Успех — `200 OK`:

```json
{
  "items": [
    {
      "id": 12,
      "title": "Студенческая конференция",
      "excerpt": "Регистрация докладов открыта до конца месяца.",
      "targetRole": "student",
      "status": "published",
      "publishedAt": "2026-08-04T10:00:00.000Z",
      "createdAt": "2026-08-03T10:00:00.000Z",
      "updatedAt": "2026-08-04T10:00:00.000Z",
      "author": { "id": 1, "fullName": "Администратор" }
    }
  ],
  "pagination": { "page": 1, "limit": 20, "total": 1, "totalPages": 1 }
}
```

Список специально не возвращает `bodyMarkdown`: его достаточно запрашивать
только при переходе на страницу новости.

### GET `/api/news/:id`

Возвращает ту же информацию и дополнительное поле с исходным Markdown:

```json
{
  "id": 12,
  "title": "Студенческая конференция",
  "excerpt": "Регистрация докладов открыта до конца месяца.",
  "bodyMarkdown": "## Конференция\n\nРегистрация открыта до **31 августа**.",
  "targetRole": "student",
  "status": "published",
  "publishedAt": "2026-08-04T10:00:00.000Z",
  "createdAt": "2026-08-03T10:00:00.000Z",
  "updatedAt": "2026-08-04T10:00:00.000Z",
  "author": { "id": 1, "fullName": "Администратор" }
}
```

Backend хранит Markdown, но не преобразует его в HTML. Клиент обязан безопасно
рендерить Markdown; raw HTML следует отключить либо пропускать через sanitizer.

## Управление новостями

Все маршруты `/api/admin/news/**` требуют access token с ролью `admin` и всегда
ограничены `tenantId` администратора.

### GET `/api/admin/news`

Возвращает карточки как опубликованных новостей, так и черновиков. Поддерживает
`page`, `limit`, `search`, а также фильтры `status=draft|published` и
`targetRole=all|student|teacher|admin`.

### POST `/api/admin/news`

Создаёт черновик. Статус намеренно нельзя передать в теле — публикация является
отдельным явным действием.

```json
{
  "title": "Изменение расписания",
  "excerpt": "Занятия второй смены начнутся позже.",
  "bodyMarkdown": "# Изменение расписания\n\nПодробности в **таблице** ниже.",
  "targetRole": "student"
}
```

| Поле           | Обязательно | Ограничение                              |
| -------------- | ----------: | ---------------------------------------- |
| `title`        |          да | 3–200 символов                           |
| `excerpt`      |         нет | до 500; без него формируется из Markdown |
| `bodyMarkdown` |          да | 1–100000 символов                        |
| `targetRole`   |         нет | `all`, `student`, `teacher`, `admin`     |

Успех — `201 Created`; ответ содержит детальную новость со `status: "draft"`
и `publishedAt: null`.

### GET `/api/admin/news/:id`

Возвращает детальную новость независимо от статуса и целевой роли.

### PUT `/api/admin/news/:id`

Частично обновляет `title`, `excerpt`, `bodyMarkdown` и/или `targetRole`.
Пустое тело возвращает `400`. Чтобы снова автоматически получать аннотацию из
Markdown, передайте `"excerpt": null`.

### POST `/api/admin/news/:id/publish`

Публикует новость немедленно и выставляет `publishedAt`. Повторный вызов
безопасен и сохраняет исходное время публикации. Успех — `200 OK`.

### POST `/api/admin/news/:id/unpublish`

Возвращает новость в черновики и очищает `publishedAt`. После этого пользователь
получит `404` на её detail URL. Успех — `200 OK`.

### DELETE `/api/admin/news/:id`

Физически удаляет новость и возвращает удалённый объект — `200 OK`.

Общие исходы новостей:

| Статус | Когда                                                        |
| -----: | ------------------------------------------------------------ |
|  `400` | DTO/ID некорректны, лишнее поле или пустое обновление        |
|  `401` | access token отсутствует или некорректен                     |
|  `403` | для admin-маршрута роль пользователя не `admin`              |
|  `404` | новость не найдена, не опубликована или недоступна этой роли |
|  `429` | превышен rate limit                                          |

## Пока не реализовано

Следующие routes существуют как технические заглушки и пока возвращают
`{"message":"TODO: ..."}`. Frontend не должен считать ответ `2xx` признаком
готовой функции:

- `POST /api/admin/users/import`;
- `POST /api/submissions/:id/grade`;
- `GET/POST /api/assignments/:assignmentId/chat`;
- `GET/POST /api/materials`.

Курсы, шаблоны, блоки, задания, уведомления и course-scoped материалы уже имеют
рабочие контракты. Отдельные `/api/materials` остаются legacy-заглушками.

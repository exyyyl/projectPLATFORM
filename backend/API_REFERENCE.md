# API Reference

Документ описывает только реализованные маршруты. Заглушки перечислены отдельно
и не считаются готовым API-контрактом.

Интерактивная документация после запуска backend:

- Swagger UI: `http://localhost:3000/docs`
- OpenAPI JSON: `http://localhost:3000/docs-json`

## Общие правила

| Параметр           | Значение                              |
| ------------------ | ------------------------------------- |
| Локальный base URL | `http://localhost:3000`               |
| API prefix         | `/v1`                                 |
| Формат тела        | `application/json`                    |
| Access token       | `Authorization: Bearer <accessToken>` |
| Refresh token      | HttpOnly cookie `refreshToken`        |
| Время              | ISO 8601, UTC                         |

Глобальный `ValidationPipe` удалять неизвестные поля не будет: запрос с лишним
полем получит `400 Bad Request`.

Стандартная ошибка NestJS:

```json
{
  "statusCode": 400,
  "message": ["property role should not exist"],
  "error": "Bad Request"
}
```

`message` может быть строкой или массивом сообщений валидации.

## Auth

### POST `/v1/auth/register`

Создаёт студента и сразу выдаёт пару токенов. Маршрут доступен только гостю:
активный access token или действующая refresh-сессия дают `403`.

Тело:

```json
{
  "email": "new-student@example.com",
  "password": "password123",
  "name": "Новый студент"
}
```

| Поле       | Тип    | Обязательно | Ограничения        |
| ---------- | ------ | ----------: | ------------------ |
| `email`    | string |          да | корректный email   |
| `password` | string |          да | минимум 8 символов |
| `name`     | string |         нет | имя пользователя   |

Успех — `201 Created`:

```json
{
  "accessToken": "<jwt>"
}
```

Дополнительно сервер устанавливает cookie:

```http
Set-Cookie: refreshToken=<jwt>; HttpOnly; SameSite=Strict; Path=/
```

| Статус | Когда                                            |
| -----: | ------------------------------------------------ |
|  `201` | пользователь создан                              |
|  `400` | DTO не прошёл валидацию или переданы лишние поля |
|  `401` | передан некорректный access token/header         |
|  `403` | пользователь уже авторизован                     |
|  `409` | email уже существует или tenant ещё не настроен  |
|  `429` | превышен глобальный rate limit                   |

Текущее dev-поведение: регистрация добавляет пользователя в первый настроенный
tenant. До production необходимо добавить явное определение tenant по домену или
приглашению.

### POST `/v1/auth/login`

Авторизует активного пользователя по email и паролю. Доступен только гостю.

Тело:

```json
{
  "email": "student@demo.local",
  "password": "demo123"
}
```

Успех — `201 Created`:

```json
{
  "accessToken": "<jwt>"
}
```

Refresh token возвращается только в HttpOnly cookie.

| Статус | Когда                                                      |
| -----: | ---------------------------------------------------------- |
|  `201` | email и пароль корректны                                   |
|  `400` | некорректный email, тип поля или лишнее поле               |
|  `401` | неверные credentials либо некорректный access token/header |
|  `403` | уже существует активная access/refresh-сессия              |
|  `429` | превышен rate limit                                        |

### POST `/v1/auth/refresh`

Тело не требуется. Читает cookie `refreshToken`, отзывает использованный refresh
token и возвращает новую пару. Повторное использование старой cookie невозможно.

Успех — `201 Created`:

```json
{
  "accessToken": "<new-jwt>"
}
```

Также устанавливается новая cookie `refreshToken`.

| Статус | Когда                                                            |
| -----: | ---------------------------------------------------------------- |
|  `201` | refresh token действителен и успешно ротирован                   |
|  `401` | cookie отсутствует, истекла, отозвана или имеет неверную подпись |
|  `429` | превышен rate limit                                              |

### POST `/v1/auth/logout`

Тело не требуется. Если refresh cookie существует, её запись удаляется из БД.
Cookie очищается в любом случае, поэтому повторный logout безопасен.

Успех — `201 Created`:

```json
{
  "message": "Logged out"
}
```

## Профиль пользователя

Все маршруты раздела требуют access token.

### GET `/v1/users/me`

Возвращает активного пользователя только внутри `tenantId` из access token.

Успех — `200 OK`:

```json
{
  "id": 4,
  "tenantId": 1,
  "email": "student@demo.local",
  "fullName": "Иван Студентов",
  "role": "student",
  "isActive": true,
  "createdAt": "2026-05-24T06:35:18.320Z",
  "updatedAt": "2026-05-24T06:35:18.320Z"
}
```

`passwordHash` не возвращается.

| Статус | Когда                                                        |
| -----: | ------------------------------------------------------------ |
|  `200` | профиль найден                                               |
|  `401` | access token отсутствует/некорректен либо аккаунт недоступен |
|  `429` | превышен rate limit                                          |

### PUT `/v1/users/me`

Изменяет имя, пароль или оба поля. Изменять `email`, `role`, `tenantId` и
`isActive` через этот маршрут нельзя.

Только имя:

```json
{
  "fullName": "Новое имя"
}
```

Имя и пароль:

```json
{
  "fullName": "Новое имя",
  "currentPassword": "старый-пароль",
  "newPassword": "новый-пароль"
}
```

| Поле              | Тип    |      Обязательно | Ограничения                       |
| ----------------- | ------ | ---------------: | --------------------------------- |
| `fullName`        | string |              нет | после trim от 2 до 200 символов   |
| `currentPassword` | string | при смене пароля | передаётся вместе с `newPassword` |
| `newPassword`     | string | при смене пароля | от 8 до 72 символов               |

Успех — `200 OK`: публичный объект пользователя в том же формате, что у
`GET /v1/users/me`.

После смены пароля все refresh-сессии пользователя отзываются. Текущий access
token продолжает работать до своего истечения.

| Статус | Когда                                                                               |
| -----: | ----------------------------------------------------------------------------------- |
|  `200` | профиль обновлён                                                                    |
|  `400` | пустое тело, лишние поля, неверные ограничения или передано только одно поле пароля |
|  `401` | access token/аккаунт недоступен либо текущий пароль неверен                         |
|  `429` | превышен rate limit                                                                 |

## Администрирование

### GET `/v1/admin/users`

Требует access token с ролью `admin`. Возвращает страницу пользователей только
из tenant текущего администратора.

Query-параметры:

| Параметр  | Тип     | По умолчанию | Ограничения                                      |
| --------- | ------- | ------------ | ------------------------------------------------ |
| `page`    | integer | `1`          | минимум `1`                                      |
| `limit`   | integer | `20`         | от `1` до `100`                                  |
| `search`  | string  | —            | поиск без учёта регистра по email и полному имени |
| `role`    | enum    | —            | `student`, `teacher` или `admin`                  |
| `isActive`| string  | —            | `true` или `false`                                |

Пример:

```http
GET /v1/admin/users?page=1&limit=20&search=иван&role=student&isActive=true
```

Успех — `200 OK`:

```json
{
  "items": [
    {
      "id": 4,
      "tenantId": 1,
      "email": "student@demo.local",
      "fullName": "Иван Студентов",
      "role": "student",
      "isActive": true,
      "createdAt": "2026-05-24T06:35:18.320Z",
      "updatedAt": "2026-05-24T06:35:18.320Z"
    }
  ],
  "pagination": {
    "page": 1,
    "limit": 20,
    "total": 1,
    "totalPages": 1
  }
}
```

| Статус | Когда                                    |
| -----: | ---------------------------------------- |
|  `200` | список получен                           |
|  `400` | query-параметры не прошли валидацию      |
|  `401` | access token отсутствует или некорректен |
|  `403` | роль пользователя не `admin`             |
|  `429` | превышен rate limit                      |

### POST `/v1/admin/users`

Создаёт пользователя в tenant текущего администратора. `tenantId` нельзя
передать в теле запроса.

```json
{
  "email": "new-user@demo.local",
  "fullName": "Новый пользователь",
  "role": "student",
  "password": "password123",
  "isActive": true
}
```

| Поле       | Тип     | Обязательно | Ограничения                         |
| ---------- | ------- | ----------: | ----------------------------------- |
| `email`    | string  |          да | корректный email                    |
| `fullName` | string  |          да | после trim от 2 до 200 символов     |
| `role`     | enum    |          да | `student`, `teacher` или `admin`     |
| `password` | string  |          да | от 8 до 72 символов                 |
| `isActive` | boolean |         нет | по умолчанию `true`                 |

Успех — `201 Created`: публичный объект созданного пользователя без
`passwordHash`.

| Статус | Когда                                            |
| -----: | ------------------------------------------------ |
|  `201` | пользователь создан                              |
|  `400` | DTO не прошёл валидацию или есть неизвестное поле |
|  `401` | access token отсутствует или некорректен         |
|  `403` | роль пользователя не `admin`                     |
|  `409` | email уже занят внутри tenant                    |
|  `429` | превышен rate limit                              |

### GET `/v1/admin/users/:id`

Возвращает публичный объект пользователя, только если он принадлежит tenant
текущего администратора. Чужой tenant и несуществующий ID одинаково дают `404`.

| Статус | Когда                                    |
| -----: | ---------------------------------------- |
|  `200` | пользователь найден                     |
|  `400` | `id` не является целым числом           |
|  `401` | access token отсутствует или некорректен |
|  `403` | роль пользователя не `admin`             |
|  `404` | пользователь в текущем tenant не найден  |

### PUT `/v1/admin/users/:id`

Изменяет одно или несколько разрешённых полей пользователя:

```json
{
  "fullName": "Новое имя",
  "role": "teacher",
  "password": "new-password",
  "isActive": true
}
```

Разрешены `email`, `fullName`, `role`, `password`, `isActive`. Пустое тело
получит `400`. Нельзя изменить `tenantId`. Администратор также не может снять
с себя роль `admin` или деактивировать собственный аккаунт.

При изменении email, пароля, роли или деактивации все refresh-сессии изменяемого
пользователя отзываются. Уже выданный access token действует до истечения TTL.

Успех — `200 OK`: обновлённый публичный объект пользователя.

| Статус | Когда                                                  |
| -----: | ------------------------------------------------------ |
|  `200` | пользователь обновлён                                  |
|  `400` | некорректное/пустое тело или запрещённое изменение себя |
|  `401` | access token отсутствует или некорректен               |
|  `403` | роль пользователя не `admin`                           |
|  `404` | пользователь в текущем tenant не найден                |
|  `409` | новый email уже занят внутри tenant                    |

### DELETE `/v1/admin/users/:id`

Выполняет безопасное удаление: строка пользователя и связанные учебные данные
не удаляются, вместо этого устанавливается `isActive=false` и отзываются все
refresh-сессии. Текущий администратор не может деактивировать сам себя.

Успех — `200 OK`: публичный объект пользователя с `isActive: false`.

| Статус | Когда                                                 |
| -----: | ----------------------------------------------------- |
|  `200` | пользователь деактивирован                            |
|  `400` | некорректный ID или попытка деактивировать самого себя |
|  `401` | access token отсутствует или некорректен              |
|  `403` | роль пользователя не `admin`                          |
|  `404` | пользователь в текущем tenant не найден               |

`POST /v1/admin/users/import` пока остаётся отдельной TODO-заглушкой: импорт CSV
будет реализован после CRUD групп, поскольку для импорта нужно валидировать и
назначать учебные группы.

## Служебные маршруты

### GET `/health`

Публичный healthcheck без префикса `/v1`.

```json
{
  "status": "ok",
  "timestamp": "2026-07-29T12:00:00.000Z"
}
```

### GET `/v1`

Публичная проверка приложения. Сейчас возвращает plain text:

```text
Hello World!
```

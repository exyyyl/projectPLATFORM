# Курсы, группы и выпуск материалов

> Статус решения: принято как основа учебного контента.

## Текущая реализация: один запуск для нескольких групп

`Course` — подготовленное преподавателем содержание дисциплины. Преподаватель
может создать его заранее со статусом `draft`, наполнить материалами и только
потом опубликовать. Группы подключаются к курсу через `CourseGroup`, который
ссылается на существующий `TeachingAssignment`.

```text
Teacher + Discipline + Group
              │
      TeachingAssignment
              │
          CourseGroup
              │
            Course
```

Это не позволяет подключить к курсу произвольную группу или другого
преподавателя и не требует копировать одинаковые материалы **в рамках одного
учебного запуска**.

Текущий `Course` одновременно играет роль содержания и запуска. Для повторения
дисциплины в следующем учебном году этого недостаточно: подключение группы
ИП1-1-26 к тому же `Course`, где раньше училась ИП1-1-25, смешает историю двух
наборов.

## Реализованная основа для следующих учебных лет

Модель разделена следующим образом:

```text
CourseTemplate (переиспользуемая структура и контент)
        │
        ├── CourseRun 2025/2026 ── группы набора 2025 ── архив
        │
        └── CourseRun 2026/2027 ── группы набора 2026 ── активный запуск
```

В Prisma конкретный запуск пока сохраняет имя `Course`. Он хранит учебный
год/семестр, преподавателя, подключённые
`TeachingAssignment`, состояние публикации и собственную историю. Завершённый
запуск архивируется и не меняется при редактировании шаблона.

При создании нового запуска из шаблона:

- сейчас копируются блоки, задания и их порядок;
- материалы шаблона и их относительный график будут добавлены на этапе MinIO;
- неизменяемые файлы можно переиспользовать по ссылке на один объект MinIO, не
  копируя байты;
- абсолютные даты старого года не копируются;
- групповые `publish_now`, `schedule` и `withhold` не копируются;
- дедлайны и даты появления задаются заново либо вычисляются из относительных
  смещений шаблона, например «через 7 дней после начала курса».

Таким образом, дата `07.10.2025` не превращается слепо в дату нового запуска.
Если в шаблоне записано смещение `+21 день`, а новый запуск начинается
`01.09.2026`, базовая дата будет рассчитана как `22.09.2026`. Преподаватель
сможет изменить её для всего запуска или отдельно для конкретной группы.

## Выпуск материала

У материала есть `defaultAvailableAt`. При подключении группы создаётся
отдельный `MaterialRelease` для каждой пары «материал + группа».

При создании материала преподаватель может сразу задать общую дату
`defaultAvailableAt`, запланировать её позже или оставить материал закрытым.
Чтобы студент увидел материал, сам курс должен быть опубликован, а выпуск для
его группы должен иметь наступившую дату/статус публикации.

Пример для базовой даты 7 октября:

| Группа | Действие преподавателя | Итог |
| --- | --- | --- |
| ИП1-1-22 | `publish_now` 1 октября | материал доступен с 1 октября |
| ИП1-2-22 | `schedule` на 10 октября | материал доступен с 10 октября |
| новая группа | `inherit` | наследует базовую дату 7 октября |

Доступные действия:

- `inherit` — вернуть общую дату материала;
- `schedule` — назначить отдельную дату группе;
- `publish_now` — немедленно открыть материал группе;
- `withhold` — удерживать материал закрытым без даты.

`createdAt` хранит дату добавления материала, `updatedAt` — дату последнего
изменения. Уже опубликованные выпуски не переносятся при изменении общей даты.

## Прогресс группы

Прогресс вычисляется по заданиям курса со статусом `published` или `closed`.
Для каждого студента возвращаются:

- количество отправленных заданий;
- количество проверенных заданий;
- количество успешно пройденных заданий;
- количество работ, ожидающих проверки;
- процент прогресса — проверенные задания / все доступные задания.

Для балльного задания наличие оценки означает прохождение. Для `pass_fail`
успешное прохождение учитывается только при результате `passed`.

## Уведомления

Ручной `publish_now` сразу создаёт уведомления всем активным студентам целевой
группы. Уведомление хранит человекочитаемые `title`, `body` и структурированный
`data` с ID материала, курса, дисциплины, преподавателя и группы.

Для автоматических выпусков по расписанию следующим этапом нужен фоновый worker:

1. находит `scheduled`-выпуски с наступившей датой;
2. атомарно переводит их в `published`;
3. создаёт уведомления студентам;
4. записывает `notifiedAt`, чтобы не отправлять событие дважды.

Тот же подход применяется к будущим событиям:

- опубликовано новое задание — уведомить студентов группы;
- преподаватель выставил оценку — уведомить только автора работы;
- опубликована новость — уведомить пользователей подходящей роли.

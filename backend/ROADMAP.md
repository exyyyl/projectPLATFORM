# Roadmap backend-разработки

План построен вертикальными срезами: каждый этап должен заканчиваться рабочими
маршрутами, DTO-валидацией, проверкой ролей, tenant-изоляцией и тестами.

## 0. Стабилизация фундамента

- [x] Prisma schema, миграции и повторяемый seed.
- [x] JWT access/refresh, ротация refresh-токенов и logout.
- [x] Глобальная JWT-защита, `@Public()` и RBAC через `@Roles()`.
- [x] Проверка активности пользователя и tenant на каждом защищённом запросе.
- [x] Явный CORS allowlist с отказом запуска production без `CORS_ORIGIN`.
- [x] Профиль текущего пользователя: `GET/PUT /users/me`.
- [ ] Проверка обязательных переменных окружения при запуске.
- [x] Удаление устаревшего дубликата `src/modules/auth`.
- [ ] Единый формат ошибок и базовое логирование запросов.

## 1. Администрирование

- [x] Tenant-scoped CRUD пользователей с пагинацией и фильтрами.
- [x] CRUD групп и назначение студентов в группы.
- [x] CRUD дисциплин, назначение преподавателей и групп.
- [x] Тройные назначения `преподаватель → дисциплина → группа`.
- [x] CRUD Markdown-новостей, черновики, публикация и аудитория по роли.
- [ ] Импорт пользователей из CSV с предварительной проверкой.
- [ ] Запись административных действий в `audit_logs`.
- [ ] Ближе к завершению admin dashboard: безопасный выбор суперадминистратором
      активного tenant, короткоживущий tenant-context и обязательный аудит
      действий реального пользователя. Не принимать произвольный `tenantId` из
      body/header.

## 2. Учебная структура

- [x] Role-scoped выдача `teachingAssignments` через `/academic/overview`:
      студент видит дисциплины и преподавателей своих групп, преподаватель — свои
      дисциплины и группы, администратор — все назначения tenant.
- [x] Выдача доступных курсов с учётом роли и группы.
- [x] Связать доступ к курсу с `teachingAssignments`, чтобы студент получал курс
      только для своей группы, дисциплины и назначенного преподавателя.
- [x] Разделить переиспользуемый `CourseTemplate` и конкретный запуск `Course`
      на учебный год/семестр; запуск хранит template version и отдельный снимок.
- [x] Создание нового запуска для следующего набора: копировать блоки и задания,
      пересчитывать относительные дедлайны и не менять старый запуск.
- [ ] Добавить в шаблон материалы и относительные даты их выпуска; связать с
      MinIO без физического дублирования неизменяемых файлов.
- [ ] Архивировать завершённый запуск с сохранением неизменяемой истории групп,
      материалов, заданий, сдач и оценок.
- [x] Базовое read-only архивирование запуска; полный исторический сценарий
      завершить после submissions/grades.
- [x] CRUD блоков шаблона и запуска для преподавателя и администратора.
- [x] CRUD заданий с переходами `draft → published → closed`.
- [ ] Учебные материалы: ссылки и файлы.

## 3. Файлы и MinIO

- [x] Загрузка файлов сдачи через backend в MinIO.
- [x] Проверка размера, расширения, MIME и magic bytes для сдач.
- [x] Закрытые объекты в MinIO и короткоживущие presigned URL для сдач.
- [ ] Фоновая очистка потерянных файлов; синхронный rollback уже реализован.
- [x] Для ответов студентов принять и реализовать лимиты количества файлов,
      размера одного файла/попытки, расширений, MIME, magic bytes и попыток.

## 6. Подготовка к эксплуатации

- [ ] Полное Swagger-описание и примеры ответов.
- [ ] Строгие production rate limits для auth и тяжёлых операций — обязательный
      release blocker, см. `SECURITY_BACKLOG.md`.
- [x] Базовые негативные multi-tenant/ownership security-тесты.
- [ ] Расширить security-тесты на assignments, submissions, grades и files после
      реализации этих модулей.
- [ ] Structured logging, health/readiness checks и метрики.
- [ ] Самым последним production-этапом подключить Redis как общий сервис: сначала
      распределённый rate limit и очередь/worker выпусков, затем измеренный
      cache-aside для безопасных tenant/user-scoped чтений (`CACHING.md`).
- [ ] Production-конфигурация, backup/restore PostgreSQL и CI.
- [ ] Выполнить обязательный pre-production gate из `SECURITY_BACKLOG.md`, включая
      обновление зависимостей и повторный `npm audit`.

Документы для согласования: `FRONTEND_CORS.md`, `COURSE_RELEASES.md`,
`SUPERADMIN.md`, `CACHING.md`, `SECURITY_BACKLOG.md`. Полный фактический срез
всего репозитория хранится в корневом `PROJECT_STATUS.md`.

## Definition of Done для маршрута

1. Входные данные описаны DTO и проверяются `ValidationPipe`.
2. Доступ ограничен JWT, ролью и `tenantId`.
3. В ответ не попадают `password_hash`, токены и внутренние поля.
4. Ошибочные сценарии возвращают подходящий HTTP-код.
5. Контракт запроса, ответа и ошибок добавлен в `API_REFERENCE.md`.
6. Есть unit- или e2e-тесты, проходят `build`, `test` и `test:e2e`.

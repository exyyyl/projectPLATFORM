# Создание первого суперадминистратора

Суперадминистратор намеренно не создаётся общим demo-seeder: известная пара
email/пароль не должна существовать в production. Первый аккаунт создаётся
одноразовой CLI-командой после создания tenant и применения миграций.

## Интерактивный запуск

```bash
cd backend
npm run superadmin:create -- --email owner@example.com --name "Владелец платформы" --tenant-domain demo.local
```

Команда дважды запросит пароль в терминале и не покажет его на экране. Требования:

- минимум 12 символов;
- максимум 72 UTF-8 байта из-за ограничения bcrypt;
- demo-пароли отклоняются;
- email не должен принадлежать другому пользователю;
- указанный tenant должен существовать и быть активным.

Текущая схема требует для суперадминистратора домашний `tenantId`, хотя его
роль позволяет выполнять глобальные операции. При реализации отдельной
глобальной модели аккаунтов это ограничение будет пересмотрено.

## Автоматизированное окружение

В CI/Coolify пароль можно передать через защищённый secret
`SUPERADMIN_PASSWORD`. Не следует указывать пароль аргументом команды: аргументы
могут попасть в историю shell и список процессов.

Если production-образ установлен без devDependencies и в нём нет `ts-node`,
после `npm run build` запускается скомпилированная команда:

```bash
node dist/scripts/create-superadmin.js --email owner@example.com --name "Владелец платформы" --tenant-domain example.com
```

Команда создаёт только новый аккаунт и намеренно не перезаписывает пароль уже
существующего пользователя. Для восстановления доступа позднее должен быть
отдельный контролируемый процесс reset/recovery с аудитом.
